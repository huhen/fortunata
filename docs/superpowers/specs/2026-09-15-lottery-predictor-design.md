# Дизайн: сайт-«предсказатель» лотереи «Fortunata»

Дата: 2026-09-15
Статус: согласован с заказчиком

## 1. Цель

Веб-приложение для игры «Fortunata» (7 чисел из 1–35 + 1 число из 1–54):

1. **Архив результатов**: просмотр / добавление / редактирование / удаление прошедших розыгрышей. Запись защищена паролем (без имён пользователей).
2. **Генератор билетов**: выдаёт N билетов (по умолчанию 10). Числа, часто выпадавшие в прошлых розыгрышах, получают повышенный приоритет.

Автоматический парсинг результатов — вне скоупа; в админке показывается подсказка-источник: <https://timelottery.ru/arhiv/rezultaty-vseh-rozygryshej-fortunata/>.

## 2. Нефункциональные требования

- Оптимизация под мобильный телефон (одна колонка, тач-цели ≥ 44 px, ноль горизонтального скролла).
- Развёртывание через `docker compose`; HTTPS терминирует внешний Traefik.
- Нагрузка минимальная — SQLite без внешних зависимостей.
- Единственный язык интерфейса — русский.

## 3. Стек и архитектура

- **Бэкенд:** Go (stdlib `net/http` с маршрутизацией Go 1.22+, шаблоны не нужны). Драйвер SQLite — `modernc.org/sqlite` (pure Go, без CGO).
- **Фронтенд:** статические `index.html` / `admin.html` + ванильный JS, без npm и билд-шага. Статика зашита в бинарник через `go:embed`.
- **Подход:** статика + JSON API (SPA-lite). Серверный рендеринг и SPA-фреймворки отклонены.

```
generator/
├── cmd/server/main.go      # конфиг из env, http.ServeMux, graceful shutdown
├── internal/
│   ├── store/              # SQLite: CRUD розыгрышей
│   ├── generate/           # взвешенный генератор (частоты подаются извне)
│   ├── auth/               # пароль, подписанные cookie-сессии
│   └── api/                # HTTP-хендлеры, валидация, middleware
├── web/                    # index.html, admin.html, app.js, admin.js, style.css
├── Dockerfile
├── compose.yaml            # прод: за Traefik
├── compose.local.yaml      # локальный прогон: порт 8080, тестовые пароли
├── .env.example
└── README.md
```

Изоляция пакетов: `store` не знает про HTTP; `generate` получает частоты, сам в базу не ходит; `auth` независим. Каждый пакет тестируется отдельно.

## 4. Данные

Таблица `draws`:

| поле | тип | ограничения |
|---|---|---|
| `draw_no` | INTEGER | PRIMARY KEY — номер розыгрыша, ≥ 1 |
| `n1..n7` | INTEGER | каждый в 1–35, все семь различны |
| `bonus` | INTEGER | 1–54 |
| `created_at`, `updated_at` | TEXT | UTC, служебные |

- Порядок чисел значения не имеет: при записи семёрка сортируется по возрастанию.
- Файл БД: `/data/generator.db`, режим WAL, docker volume `data`.
- Пустая база — валидное состояние: генератор работает равномерно.

## 5. Алгоритм генерации

1. Частоты по сохранённым розыгрышам: для 1–35 — вхождения в основную семёрку; для 1–54 — вхождения в бонус.
2. Вес числа: `w(x) = count(x) + 1` (сглаживание, чтобы «холодные» числа сохраняли шанс).
3. Семёрка: взвешенный выбор без повторений — 7 извлечений по одному (накопительная сумма по 35 числам).
4. Бонус: одно взвешенное извлечение из 1–54.
5. Билет: семёрка по возрастанию, формат `02 19 26 03 14 34 07 + 48`.
6. Пачка: `count` билетов (по умолчанию 10, максимум 100). Дубликаты билетов внутри пачки отсеиваются повторной генерацией (до 20 попыток на билет, далее принимается дубликат).
7. ГСЧ: `crypto/rand`, изолирован интерфейсом для детерминированных тестов.

## 6. API и авторизация

| Метод | Путь | Доступ | Назначение |
|---|---|---|---|
| POST | `/api/login` | публично | `{password}` → cookie; неверно → 401 + пауза 1 с |
| POST | `/api/logout` | — | сброс cookie |
| GET | `/api/me` | публично | `{authenticated}` — состояние сессии для админ-страницы |
| GET | `/api/draws` | публично | список, по `draw_no` убыв. |
| POST | `/api/draws` | сессия | создать; существующий `draw_no` → 409 |
| PUT | `/api/draws/{no}` | сессия | заменить комбинацию (номер не меняется) |
| DELETE | `/api/draws/{no}` | сессия | удалить розыгрыш |
| POST | `/api/generate` | публично | `{count}` → `{tickets:[{numbers,bonus}]}` |

- **Сессия:** cookie `session = <expiry-unix> + "." + hex(HMAC-SHA256(SESSION_SECRET, expiry))`, HttpOnly, SameSite=Strict, Max-Age 7 дней. Серверного хранилища сессий нет.
- **Пароль:** `ADMIN_PASSWORD` из env, сравнение `crypto/subtle.ConstantTimeCompare`.
- **SESSION_SECRET:** если не задан — генерируется случайный при старте, warning в лог (сессии слетают при рестарте).
- **Валидация:** все ошибки → 400 с человеческим сообщением на русском (показывается под полем).
- **CSRF:** SameSite=Strict + обязательный `Content-Type: application/json` на мутациях.
- **Флаг `COOKIE_SECURE`:** `true` → cookie c `Secure` (за Traefik), локально `false`.

## 7. UI (mobile-first, русский)

Общее: системный шрифт, без внешних ресурсов, тёмная тема через `prefers-color-scheme`, `viewport-fit=cover`.

**`/` — публичная**, две вкладки:
- «Генератор»: ввод количества (цифровая клавиатура, по умолчанию 10), кнопка «Сгенерировать», билеты крупными «шарами» — семёрка отсортирована, бонус выделен цветом.
- «Архив»: список розыгрышей (номер + комбинация), только чтение.
- Ссылка на `/admin`.

**`/admin`:**
- Без сессии — форма ввода пароля.
- С сессией:
  - форма добавления: номер розыгрыша + одно текстовое поле комбинации с умным парсингом: принимает `"02, 19, 34, 07, 26, 03, 14 и 48"`, разделители — запятые/пробелы/«и», ведущие нули допустимы; клиентская валидация 7 уникальных из 1–35 + 1 из 54;
  - подсказка-источник со ссылкой на timelottery.ru;
  - список розыгрышей: «Изменить» (заполняет форму; номер розыгрыша при этом заблокирован — изменить номер нельзя, только удалить и создать заново) / «Удалить» (с подтверждением);
  - кнопка «Выйти».

## 8. Деплой

**Dockerfile:** multi-stage `golang:1.26-alpine` → `CGO_ENABLED=0 go build -ldflags="-s -w"` → `scratch`, non-root numeric UID, статика из `go:embed`. Healthcheck не нужен.

**compose.yaml (прод):**
- `restart: unless-stopped`; порты наружу не публикуются.
- labels Traefik: `Host(${DOMAIN:?})`, entrypoints `websecure`, `tls.certresolver=${TRAEFIK_CERTRESOLVER:?}`, `traefik.docker.network=${TRAEFIK_NETWORK:-traefik}`.
- Сеть: external, имя `${TRAEFIK_NETWORK:-traefik}`.
- env: `ADMIN_PASSWORD`, `SESSION_SECRET`, `DOMAIN`, `TRAEFIK_CERTRESOLVER` (обязательные), `COOKIE_SECURE` (дефолт `true`).
- Volume `data:/data`.

**compose.local.yaml (локальный тест):** `ports: 8080:8080`, тестовые `ADMIN_PASSWORD`/`SESSION_SECRET`, `COOKIE_SECURE=false`, без labels Traefik.

## 9. Тестирование

1. **Unit-тесты Go** (`go test ./...`):
   - `store`: in-memory SQLite — CRUD, 409-сценарий, сортировка, валидация на уровне БД;
   - `generate`: подменный ГСЧ — веса, уникальность семёрки, диапазоны, пустая база, дедуп пачки;
   - `auth`: подпись/проверка cookie, истечение срока, constant-time сравнение;
   - `api` (httptest): 401 без сессии, 409 дубликат, 400 валидация, happy path.
2. **Интеграционный прогон:** `docker compose -f compose.local.yaml up`, браузер (Playwright) с вьюпортом 390×844: вход → добавление розыгрыша (ввод в формате «02, 19, … и 48») → редактирование → удаление → генерация. Скриншоты как доказательство.
3. **Реальный мобильный:** `http://<ip-сервера>:8080` в той же Wi-Fi-сети.
4. Инструменты разработчика: локально устанавливается Go (Ubuntu 26.04) — команды в README.

## 10. Вне скоупа (YAGNI)

- Автоматический парсинг timelottery (только подсказка-ссылка).
- Даты розыгрышей, затухание весов по свежести (можно добавить позже поверх `store`).
- Пользователи, роли, восстановление пароля.
- Кэширование, CDN, метрики.
