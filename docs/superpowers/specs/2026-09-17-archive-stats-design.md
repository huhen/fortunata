# Страница статистики по архиву — дизайн

Дата: 2026-09-17
Статус: утверждён

## Задача

Третья вкладка «Статистика» в основном интерфейсе: частоты выпадения шаров по
архиву розыгрышей. Шары отсортированы по убыванию количества выпадений, сначала
основные (1–35), затем бонусные (1–54). Номера, не выпавшие ни разу, не
отображаются. Рядом с каждым шаром — количество выпадений.

## Решения

- Подход A: сервер считает и сортирует частоты, клиент только рисует.
  Альтернатива (агрегация в JS на клиенте по `/api/draws`) отклонена: логика
  осталась бы в нетестируемом JS, а весь архив гонялся бы на клиент.
- При равном количестве выпадений — сортировка по возрастанию номера шара.
- Страница публичная, без авторизации (как «Архив»).

## Бэкенд

### Store (`internal/store/store.go`)

Новый тип и два метода:

```go
// Freq — сколько раз выпал шар N.
type Freq struct {
    N     int `json:"n"`
    Count int `json:"count"`
}

// MainFrequency — частоты основных шаров (колонки n1..n7).
// BonusFrequency — частоты бонусного шара (колонка bonus).
func (s *Store) MainFrequency() ([]Freq, error)
func (s *Store) BonusFrequency() ([]Freq, error)
```

- Один SQL-запрос на метод: подзапрос `UNION ALL` по колонкам, затем
  `GROUP BY n ORDER BY count DESC, n ASC`. Для бонуса — `GROUP BY` по `bonus`.
- Номера без выпадений в результате `GROUP BY` не появляются — отдельная
  фильтрация не нужна.

### API (`internal/api/`)

- Маршрут: `GET /api/stats` (публичный, без `h.session`).
- Ответ 200:
  `{"main":[{"n":7,"count":42},...],"bonus":[{"n":12,"count":9},...]}`
- Ошибка БД → 500 `{"error":"..."}` через существующий `errorJSON`.

## Фронтенд

### `web/index.html`

- Кнопка вкладки `<button class="tab" data-tab="stats">Статистика</button>`
  после «Архив».
- Панель `<section id="tab-stats" class="panel" role="tabpanel">` c
  `<div id="stats-list">`.

### `web/app.js`

- При переключении на вкладку `stats` — `loadStats()`: `api('/api/stats')`.
- Отрисовка: две карточки с заголовками «Основные шары» и «Бонусные». Внутри —
  flex-wrap список пар «шар + счётчик»:

  ```
  (07) 42   (12) 38   (23) 38   (05) 30  …
  ```

  Шар — существующий `ball(n)` / `ball(n, 'bonus')` из `common.js`; счётчик —
  приглушённая цифра рядом (класс `ball-count`).
- Данные загружаются при каждом открытии вкладки (как у «Архива»).

### `web/style.css`

Минимальные добавления: `.stat-list` (flex-wrap контейнер), `.stat-item`
(строка «шар + счётчик»), `.ball-count` (приглушённый цвет `var(--muted)`).
Тёмная тема и карточки наследуются от существующих переменных.

## Граничные случаи

- Пустой архив → оба списка пусты → текст «Розыгрышей пока нет — добавьте их
  через редактирование.»
- Ошибка API → текст ошибки внутри `#stats-list` (поведение как у «Архива»).
- Веб-тесты для `app.js` не пишутся: тестовая инфраструктура есть только у
  `parse.js`; отрисовка проверяется вручную при запуске.

## Тесты

- `internal/store/store_test.go`: сид из розыгрышей → `MainFrequency` и
  `BonusFrequency` возвращают частоты в правильном порядке (count по убыванию,
  при равенстве номер по возрастанию); никогда не выпадавшие номера отсутствуют.
- `internal/api/api_test.go`: `GET /api/stats` без cookie → 200 и ожидаемый
  JSON. Ветка ошибки БД (500) не тестируется — как и в существующих тестах API,
  сбой SQLite не симулируется.

## Не входит в объём

- Сводка по архиву (всего розыгрышей, диапазон номеров) — YAGNI.
- Графики/теплокарта частот.
- Статистика на странице `/admin`.
